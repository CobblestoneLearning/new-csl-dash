# The Repository Hub — staff notes

**What it is:** one page that shows everything Cobblestone Learning has built on GitHub — every
plugin, theme, snippet and tool — with a plain-English line about what each one does.

**Where it lives:** https://cobblestonelearning.github.io/new-csl-dash/
This is the *new* version, being trialled alongside the current hub at
https://cobblestonelearning.github.io/

## How to use it

1. **Sign in with GitHub** (top right). Without signing in you'll only see the handful of public
   repositories. Signed in, you see everything your account can reach — currently 109.
2. **Stay in Staff view** (the default). Projects are grouped by what they're *for*:
   reporting, course authoring, translation, the LMS platform itself, operations, internal tools
   and websites.
3. **Search** using ordinary words — "certificate", "reminder emails", "BuddyBoss". It searches
   names, descriptions and the platforms each tool works with. Watch the coloured map at the top:
   it lights up to show you where the matches are across the whole account.
4. **Press ⌘K** (Ctrl+K on Windows) anywhere to jump straight to a repository by name.
5. **Click "Open"** on any card to read its notes, and "Demo" where there is one — some tools run
   right there in the page.

## Reading the map

Each little square is one repository. The colour tells you what kind of thing it is (blue =
plugin, light blue = snippet, orange = theme, green = app or tool, pink = website). Darker means
more recently worked on. A small white dot means you can open it here without leaving the page.

## The snippet library

Further down there's a separate section for the 65 **WPCode snippets** — small pieces of code
running on live client sites, mirrored here from SiteGround. Filter them by site (One Family,
Hub na nÓg, EINN…) or by what they work with. **WPCode on each site is still the source of
truth** — this is a read-only mirror, so don't edit a snippet here expecting the site to change.

## Something missing or filed wrongly?

Every project should have a one-line description on GitHub and a `CLREADME.md` like this one.
If a card says "no description on GitHub yet", or a tool is sitting under the wrong heading,
that's fixed on the repository itself — add a description, or a `cat-…` topic. Ask Bryan if
you're not sure which.
